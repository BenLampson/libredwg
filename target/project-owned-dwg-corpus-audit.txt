LibreDWG project-owned DWG corpus Stream audit
==============================================

Audit date: 2026-07-11
Source: project-owned private CAD quantity-estimation material

Privacy and repository boundary
-------------------------------

The source files are local project material. They were read in place and were
not copied, modified, downloaded, or committed. This record intentionally omits
business filenames, absolute paths, drawings, and content hashes. It retains
only the aggregate evidence needed to maintain the C Stream target.

Version classification
----------------------

The corpus contains 21 unique DWG files with this exact decoded distribution:

  R2000: 6
  R2004: 6
  R2007: 4
  R2010: 2
  R2013: 1
  R2018: 2

Every file uses a final public format identifier and final internal version.
No R2000b, R2004a/c, R2007a/b, R2010b, R2013b, or R2018b file is present, so
this corpus does not close any of the eight modern beta/development evidence
gaps.

One additional R2004 file reports structural warning 0x40 during probing. The
normal blocking baseline produces no comparable object set in the strict
harness, while a Stream-only diagnostic can traverse a large object sequence.
The project owner also reports that forcing this file open previously consumed
32 GB of memory. These observations are recorded without claiming a completed
corruption diagnosis.

Abnormal R2004 input exclusion
------------------------------

The project owner classifies this file as an abnormal input and excludes it
from the supported business corpus. It is not a pending decoder investigation,
not a Stream-parity completion gate, and must not reduce the accepted corpus
result below 20/20. Its private identity remains known outside the repository;
the filename, path, binary, and content hash are not committed here.

This exclusion does not claim that arbitrary malformed DWGs are supported. If
malformed-input resource limits become a separate future target, use this file
only under that explicitly changed scope.

---------------------------

`result.md` records the 20 accepted inputs with blocking and pure Stream elapsed
time, process peak working set, and object counts. At the project owner's
request it identifies each input by filename, but records no absolute path,
binary, or content hash. The benchmark totals reproduce this audit's 6,347,881
objects,
5,410,837 entities, 937,044 non-entities, zero Stream decode errors, and
20/20 accepted-file result.
