-------------------------------

Its private local identity is known outside the repository. Initial strict
testing does not establish blocking-versus-Stream parity: the normal blocking
baseline produces no comparable object set in the strict harness, while a
Stream-only diagnostic can traverse a large object sequence. The diagnostic
was stopped after classification; no success result is claimed.

Keep this item open as a dedicated decoder investigation. Completion requires
all of the following:

1. identify the exact source of warning 0x40 and the blocking baseline result;
2. define whether the file is valid, recoverable, or structurally corrupt;
3. make blocking and Stream behavior agree under the applicable policy;
4. run the strict C comparison with zero unaccounted decode errors and full=0;
5. update this record before counting the file in project-corpus parity.

Do not let the other five clean R2004 files or the broader 20-file result close
this dedicated item.
