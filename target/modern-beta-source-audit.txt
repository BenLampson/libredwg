LibreDWG modern beta/development DWG source audit
=================================================

Audit date: 2026-07-11
Scope: independently sourced historical files for the active DWG 2000+
       blocking-versus-Stream parity queue

Active unresolved queue
-----------------------

R_2000b  AC1500
R_2004a  AC402a
R_2004c  AC1018 with internal version 0x18
R_2007a  AC701a
R_2007b  AC1021 with internal version 0x1a
R_2010b  AC1024 with internal version 0x1c
R_2013b  AC1027 with internal version 0x1e
R_2018b  AC1032 with internal version 0x20

The first, second, and fourth entries have distinct six-byte file magic. The
other entries share release-family magic and therefore require the decoded
common-header version; filename, product year, and six-byte magic alone are
not sufficient evidence.

Authoritative identifier check
------------------------------

Autodesk's ObjectARX managed reference lists AC2100a=0x1a,
AC2400a=0x1c, AC2700a=0x1e, and AC3200a=0x20 in DwgVersion, alongside the
corresponding final values AC1021=0x1b, AC1024=0x1d, AC1027=0x1f, and
AC1032=0x21:

https://help.autodesk.com/view/OARX/2026/ENU/?guid=OARX-ManagedRefGuide-Autodesk_AutoCAD_DatabaseServices_DwgVersion

This establishes that the identifiers are part of Autodesk's API contract. It
does not establish that a public historical DWG carrying any identifier is
available, and it is not real-file parity evidence.

Public archive catalog audit
----------------------------

Internet Archive advanced-search metadata was queried for AutoCAD titles and
descriptions containing beta, and separately for AutoCAD 2000, 2004, 2007,
2010, 2013, and 2018 media. On 2026-07-11 the beta query returned one item:

  autocad.7z  Autodesk AutoCAD R13 c4 beta #4

That item predates the active queue. The product-year searches returned final
media, books, training material, and unrelated uploads, but no cataloged beta
or alpha media for an active modern identifier. Search-engine queries for the
exact AC2100a, AC2400a, AC2700a, and AC3200a names returned enum/API
documentation rather than downloadable historical DWG samples.

BetaArchive catalog searches were also attempted for the six product families,
but its public pages returned a Cloudflare JavaScript challenge. No catalog or
file claim is derived from that inaccessible result.

Public GitHub repository-index audit
------------------------------------

GitHub's public repository search API was queried on 2026-07-11 with these
exact repository-level searches:

  AC1500 dwg
  AC402a dwg
  AC701a dwg
  AC2100a dwg
  AC2400a dwg
  AC2700a dwg
  AC3200a dwg
  AutoCAD beta DWG samples

Every query returned total_count=0. This is a reproducible negative result for
repository names, descriptions, and other fields indexed by that API. It is
not a content-level scan of every GitHub blob, and it does not prove that a
historical file never existed or that no unindexed/private copy exists.

Upstream AC1500 lead
--------------------

GitHub's commit index returned one relevant LibreDWG upstream commit:

  12cd6e9063fad0114db83c5654efcea665d1dbb5
  Fix assertion failure in section_move_before for R13 encoding
  Author date: 2026-06-12

Its message says an AC1500/R2000b input with six R13-family sections exposed an
encoder assertion while being re-encoded as R13. The commit was made directly
by upstream maintainer Reini Urban and changes only `src/encode.c`. It contains
no fixture, filename, hash, source provenance, or test addition. GitHub reports
no associated pull request, and repository issue searches for `AC1500` and
`R2000b` return no issue or public attachment.

This establishes only that the maintainer used some AC1500 input in 2026. It
does not establish that the input is independently sourced, historical, or
publicly retrievable, and it cannot be run through the strict C comparison.
R_2000b therefore remains open.

Upstream history for the other modern identifiers
-------------------------------------------------

Exact LibreDWG upstream commit-index searches were also run for `AC402a`,
`AC701a`, `AC2100a`, `AC2400a`, `AC2700a`, `AC3200a`, and the corresponding
`R_2004a`, `R_2004c`, `R_2007a`, `R_2007b`, `R_2010b`, `R_2013b`, and
`R_2018b` enum names.

No file-bearing historical lead was found. The only relevant-looking results
were code-boundary changes:

  70ed9972d3f72cde4064e9285d409ad14e08d453
  change versions: add R_2007a, remove unused

This 2023 commit says the version table was checked against ODA. It adds the
`AC701a` enum/header mapping but contains no DWG, test, filename, hash, or claim
that an R2007a file was decoded.

  3604335339d9865ec98131d4649a4107219f9be7
  encode: fix r2010+ object encoding for JSON/DXF import

This 2026 commit changes an encoder guard from `R_2013b` to `R_2010b`; it does
not identify an R2010b input. Other hits for `R_2004a` similarly use the enum as
a format-family boundary rather than report a development-version file.

Commit absence is not proof that the formats were never distributed. It only
establishes that upstream history currently provides no retrievable candidate
for strict blocking-versus-Stream validation. All seven gaps remain open.

Result and acceptance rule
--------------------------

No active gap is closed by this audit. All eight entries remain unresolved.
Negative catalog or repository-index search results are insufficient to label
an identifier as a format that was never historically public. Future candidates
must be classified from file contents and then pass the C strict comparison
between dwg_read_file and dwg_stream_file_ex with zero per-object decode errors
and full=0. A catalog listing, enum definition, synthetic header rewrite, or
generated fixture cannot replace that evidence.
